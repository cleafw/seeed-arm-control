# 通用机械臂控制方案 — 实施规划

> 工程目录：**seeed-arm-control**（原 `rebot-b601-102-record`）。  
> 演进目标：可插拔主/从臂 + 可选语音控制。  
> 本文只做阶段与步骤规划，不涉及具体代码实现。  
> 更新日期：2026-08-25

---

## 1. 目标与范围

### 1.1 要做成什么

| 能力 | 说明 |
|------|------|
| 主/从臂可选 | 页面选择主臂型号、从臂型号 |
| 开机自动检测 | 启动时探测已接入主/从臂型号，等待校验完成后写入配置 |
| 配套配置持久化 | 「主臂型号 × 从臂型号」对应一套校准/映射/控制参数；热拔插后能读回 |
| 热拔插 | 换臂后：有配套配置 → 加载；无配套 → 强制重新校准，完成后再保存 |
| 手动 + 自动检测 | 可手选型号；也可点「自动检测」重新探测并选中 |
| 语音可选 | 语音独立模块与接口；无算力设备不部署语音 → UI 隐藏或灰掉 |
| 语音与跟随关系 | 页面可选：跟随优先 / 语音优先 / 跟随模式下开启语音 等策略 |

### 1.2 明确不做（本规划边界）

- 第一期不实现「任意第三方臂」即插即用，只做**已登记的 Profile**（见 §3）
- 语音推理本身仍依赖 Jetson 级算力；Pi 等弱算力机**只跑跟随/录播**
- 不在同一进程内硬混两套电机协议；通过驱动适配层切换

### 1.3 工程命名（已定）

| 项 | 值 |
|------|------|
| **目录 / 产品名** | **seeed-arm-control** |
| 对外显示名 | 机械臂控制台 / Arm Control Console |
| 包/镜像名 | `arm-control`（可与旧 `rebot-record` 并存过渡） |
| 旧名 | `rebot-b601-102-record`（文档保留追溯） |

## 2. 总体架构（目标态）

```text
Browser UI
  ├─ 臂型选择 / 自动检测 / 校准 / 映射 / 录播 / 急停
  └─ 语音策略（有语音模块才显示）
        │ REST + WS
        ▼
Core（始终部署）
  ├─ Arm Registry（已支持型号清单）
  ├─ Detect Service（串口/VID/协议探测）
  ├─ Pairing Store（配套配置持久化）
  ├─ Controller 状态机（follow/record/playback/…）
  └─ Driver Adapters
        ├─ leader: Violin/102 | …（后续可扩）
        └─ follower: B601-DM | SO-ARM101 | …
        │
Voice Module（可选部署）
  ├─ ASR / LLM / TTS 编排（可仍用独立容器）
  ├─ 语音策略：follow_first / voice_first / voice_in_follow
  └─ 调 Core 的 HTTP API 或动作库（不直连电机）
```

原则：

1. **Core 与 Voice 解耦**：弱算力只装 Core；有 Jetson 再装 Voice。
2. **控制只走 Adapter**：换臂 = 换 Adapter + 换配套配置，不改状态机主干。
3. **配套配置按「主型号+从型号」键存储**，不是全局一份 calibration。

## 3. 臂型 Profile（第一期登记）

| ID | 角色 | 协议/栈 | 来源 |
|----|------|---------|------|
| `violin_102` | 主臂 | FashionStar UART / motorbridge | 现有 |
| `so101_leader` | 主臂 | LeRobot SO-ARM101 leader (ST3215) | Seeed 成套主臂 |
| `b601_dm` | 从臂 | u2can DM_CAN | 现有 |
| `so101_follower` | 从臂 | LeRobot SO-ARM101 follower | Seeed 成套从臂 |

典型配套：`violin_102__b601_dm`（现场默认）、`so101_leader__so101_follower`（SO-ARM101 成套）。

后续扩展只加 Registry + Adapter，不改 UI 骨架。

检测线索（示例）：

- CH340 `1a86:7523` → 候选主臂 `violin_102`
- HDSC CDC → 候选从臂 `b601_dm`
- SO-ARM Bus Servo USB-serial → 候选 `so101_leader` / `so101_follower`（需手选或电压/校准文件区分）

无法唯一判定时：UI 标「待确认」，要求用户手选或再点自动检测。

## 4. 配套配置（Pairing）数据模型

键：`pair_id = {leader_id}__{follower_id}`  
例：`violin_102__b601_dm`、`so101_leader__so101_follower`

每套至少包含：

| 字段 | 说明 |
|------|------|
| `leader_id` / `follower_id` | 型号 |
| `ports` | 上次成功端口（提示用，热拔插后以检测为准） |
| `calibration` | 行程映射（若该组合需要） |
| `motor_map` | 电机映射（若适用；SO-ARM 可能结构不同） |
| `control_params` | 速率、安全阈值、回零时间等 |
| `validated_at` | 校验/校准完成时间 |
| `schema_version` | 便于迁移 |

存储建议：`recordings/pairings/<pair_id>.json`（或拆分子文件，由清单索引）。

**热拔插规则：**

1. 检测到当前 leader/follower ID  
2. 查是否有该 `pair_id` 且 `validated`  
3. 有 → 加载并进入「待解锁 / follow」  
4. 无 → UI 强制校准流程，禁止跟随，直到完成并保存

## 5. 语音策略（仅 Voice 模块存在时）

| 模式 ID | UI 文案（草案） | 行为 |
|---------|-----------------|------|
| `follow_only` | 仅跟随（无语音或语音关闭） | 现有遥操 |
| `voice_in_follow` | 跟随模式中开启语音 | 跟随照常；语音可触发录播/预设动作/急停等，不抢关节流 |
| `follow_first` | 跟随优先 | 主臂有运动时语音动作排队或拒绝；空闲才执行语音 |
| `voice_first` | 语音优先 | 语音执行期间暂停主臂映射；结束后回跟随或锁定 |

能力探测：

- Core 启动时读环境变量 / 健康检查：`VOICE_ENABLED=1` 且 `http://voice-host:…/health` 可达  
- 不可达 → 页面不展示语音策略，或选项全部 disabled + 提示「本机未部署语音模块」

Voice **禁止**直接写电机；一律调用 Core API（pose / play / pause / free_move 等）。

### 阶段 2 — 自动检测 + 校验 + 持久化（约 3～4 天）

| 步骤 | 内容 | 产出 |

### 阶段 3 — 热拔插与链路状态联动（约 2～3 天）

## 7. 推荐实现顺序（给你逐步开工用）

```text
阶段 0 定名
  → 阶段 1 手选臂型 + pairing 骨架
  → 阶段 2 自动检测 + 保存配套
  → 阶段 3 热拔插
  → 阶段 4 Adapter + SO-ARM 从臂
  → 阶段 5 语音可选模块与策略
  → 阶段 6 打磨与更名收尾
```

每阶段结束再开下一阶段，避免「检测 + SO 驱动 + 语音」同时大改。

## 8. 风险与依赖

| 风险 | 应对 |
|------|------|
| 串口探测误判 | 协议探活 + UI 手选兜底 |
| 一套校准不能跨型号 | 强制 pair_id 隔离 |
| SO-ARM 与 B601 映射模型不同 | Profile 能力标志；UI 按能力显示面板 |
| 语音与跟随抢控制权 | 策略状态机 + Core 单写者 |
| Jetson 与 Pi 部署差异 | compose profiles：`core` / `core-voice` |
| 更名影响现场路径 | 先别名文档，后改目录；现场软链过渡 |
