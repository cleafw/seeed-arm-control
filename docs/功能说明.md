# rebot-b601-102-record — 功能说明

主臂（StarAi Violin / Arm-102）拖动 → 从臂（reBot B601-DM）跟随，并可把轨迹存进动作库后循环/单次回放。浏览器是唯一客户端。主臂对齐 LeRobot `rebot_102_leader`；从臂用本仓库 `u2can`。

入口：[`../SKILL.md`](../SKILL.md)。上游原文：[`../README.md`](../README.md)。架构笔记：[`../CLAUDE.md`](../CLAUDE.md)。变更摘要：[`变更记录.md`](变更记录.md)。

---

## 1. 功能清单

| 能力 | 说明 |
|------|------|
| 跟随 | 主臂读关节 → 校准映射 + 电机映射 → 从臂 30Hz 写出 |
| 录制 | 跟随的同时写入动作库（存的是**主臂空间**关节） |
| 回放 Loop / Once | 播放前在从臂空间平滑过渡到首帧；Once 结束后慢回当前主臂姿态 |
| 关节校准 | 双臂自由拖动扫行程，生成 `calibration.json` 线性映射 |
| 电机映射 | 主臂 J1–GR → 从臂电机（可「无」）+ 正向/反向，持久化 `motor_map.json` |
| 停止运行 | 解锁从臂电机（无阻尼自由拖动）；可再「恢复跟随」缓移回遥操 |
| 急停 / 解除锁定 | 急停保持位姿；解除锁定会重新握手并使能，再缓移跟随 |
| 复位 | `/api/recover`：慢回 home → 再握手（电机线重插场景） |
| 安全限速 | 主臂单 tick 跳变过大自动暂停 |
| 双臂链路状态 | 底部状态窗；断电/拔 USB 主动探活；恢复后等待解锁再跟随 |
| 常驻 | Docker `restart: unless-stopped`；串口异常**不杀进程**，就地重连 |
| Web UI | 关节遥测 + 校准栏 + 电机映射表 + 动作库 + 机械臂状态 |

状态机（`ControllerMode`）：

```text
idle ──校准完成──► follow
follow ──start_record──► record ──stop_record──► follow
follow ──play──► transition(从臂空间) ──► playback
                   ├─ loop：末尾 blend 回首帧
                   └─ once：播完 ──► return_to_follow ──► follow
follow ──free_move──► free_move ──resume──► follow（缓移）
follow ──pause──► paused ──resume──► follow（握手+缓移）
follow/idle/paused ──calibrate──► calibrate ──finish──► follow
任意模式 ──串口/断电故障──► paused(或 idle) + 重连中
重连成功 ──► paused（等待「解除锁定」）──resume──► follow
```

## 2. 架构

```text
Browser (LAN)  http://<host>:1882
  React SPA  ──HTTP REST──┐
               ──WS /ws───┤  快照约 10Hz
                          ▼
Container rebot-record
  FastAPI (uvicorn :8000)
    控制线程：读主臂 → 映射 → 写从臂 → snapshot；约 0.8s 双臂探活
      主臂：CH340 / motorbridge-smart-servo（只读，1M baud）
      从臂：HDSC CDC / u2can DM_CAN POS_VEL；夹爪 Torque_Pos
  volumes:
    recordings/  （动作库 + calibration.json + motor_map.json）
    backend/     （只读挂载，改 Python 后 recreate 即可）
```

- 串口/断电故障：更新 `arms` 状态并就地重连，**HTTP/WS 保持可用**（不再因 SerialException 整站退出）。
- 控制线程意外崩溃仍会 `SIGTERM`，交给 Docker 重启。
- `docker stop` → `safe_shutdown`（缓慢回零 + 失能）。

## 3. 硬件与端口

| 角色 | 识别 | 稳定设备名 |
|------|------|------------|
| 主臂 | VID `0x1a86` PID `0x7523`（CH340） | `/dev/rebot-master` |
| 从臂 | manufacturer `HDSC` / product `CDC*` / 或 CH343 `1a86:55d3` | `/dev/rebot-slave` |

识别靠 **USB 芯片身份**，不靠物理插口。换 USB 口后 `ttyUSB*`/`ttyACM*` 可能变号，但 udev 会重建 `/dev/rebot-*`。

仓库内规则：[`deploy/udev/99-rebot-arms.rules`](../deploy/udev/99-rebot-arms.rules)

```bash
sudo cp deploy/udev/99-rebot-arms.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
ls -l /dev/rebot-master /dev/rebot-slave
```

现场 compose：[`deploy/docker-compose.seeed.yml`](../deploy/docker-compose.seeed.yml)  
环境文件示例路径：`/home/seeed/seeed/ENV/rebot-b601-102-record.env`（`MASTER_PORT`/`SLAVE_PORT` 指向 `/dev/rebot-*`）。

电源：Violin / 主臂常见 **12V**；B601 从臂 **24V**。J1（DM4340）故障后若仍僵硬，可能需要 **24V 断电再上电**。

## 4. 校准与映射（持久化）

| 文件 | 位置 | 作用 |
|------|------|------|
| `calibration.json` | `recordings/` | 主/从各关节 min/max；跟随与回放时做线性行程映射 |
| `motor_map.json` | `recordings/` | 主臂关节 → `{slave, dir}`；`dir=+1` 正向，`-1` 行程取反 |
| `motor_map.json.bak` | 同上 | 每次保存前自动备份上一份 |

- 校准行程不足（跨度 &lt; 0.05 rad）不能完成校准。
- 映射到「无」：该从臂电机保持上次位姿。
- 一对多禁止：同一从臂电机只能被一个主臂关节占用。
- **动作库帧始终是主臂空间**；写出前再 `_map_for_slave`。

## 5. 关键 UI 行为

| 控件 | 行为 |
|------|------|
| **停止运行** | 进入 `free_move`：MIT 零力矩 / J1 失能，可自由拖动；按钮变为「恢复跟随」 |
| **恢复跟随** | 先退出 free_move（避免与 J1 disable 竞态），`enable_all` 握手，从实测位姿缓移到映射目标 |
| **急停** | `paused`：从臂保持最后命令位姿（有阻尼锁定感） |
| **解除锁定** | 与恢复类似：握手 + 缓移回跟随 |
| **电机映射表** | 改映射到具体电机需确认；改「无」不弹窗；改后从臂缓移 |
| **播放动作** | `transition` 在**从臂空间**插值到首帧映射位姿（禁止主从空间混插，否则 J1 会猛甩） |
| **机械臂状态** | 底栏一窗显示主臂/从臂：正常 / 未接入 / 串口异常 / 重连中；顶部同步提示 |

## 5.1 双臂链路探活与重连

快照字段 `arms`：

```json
{
  "master": {"id":"master","label":"主臂","status":"ok|missing|error|reconnecting|initializing","detail":"...","port":"/dev/rebot-master"},
  "slave":  {"id":"slave","label":"从臂","status":"...","detail":"...","port":"/dev/rebot-slave"},
  "ready": true,
  "hint": null
}
```

| 检测 | 方式 |
|------|------|
| USB 拔出 | `/dev/rebot-*` 节点消失，或串口 I/O 报错 |
| 仅断电（USB 仍在） | 主臂舵机 ping / 连续无新角度；从臂 refresh 无 CAN 反馈（`_rx_gen` 不增） |
| 周期 | 约 0.8s；连续 2 次失败才标异常（防抖） |

恢复流程：检测到双臂就绪 → 从臂 `recover` 握手 → 同步位姿 → **`paused` + hint「请解除锁定」** → 用户点解除锁定进入跟随。  
首次上电连上双臂：保持原模式（follow/idle），不强制进 paused。

## 10. 排障

| 现象 | 处理 |
|------|------|
| 容器反复重启 | `docker compose ... logs --tail 80`；查端口/udev；串口异常现已不杀进程，若仍重启属其它崩溃 |
| 找不到主/从臂 | 查 `lsusb`、`/dev/rebot-*`；确认 12V/24V；看底栏「机械臂状态」 |
| 关电源/拔 USB 仍显示正常 | 应在约 1–2s 内变异常；若否，确认已部署含探活的 `controller.py`/`pipermate.py` 并 recreate |
| 恢复跟随后仅 J1 不动 | 已修复 free_move 与使能竞态；仍不行则 24V 断电重上电再「复位」 |
| 播放开头 J1 猛甩一下 | 已修复 transition 主从空间混插；更新 `controller.py` 后 recreate |
| 映射改完重启丢失 | 查 `recordings/motor_map.json` 是否写入；有 `.bak` 可恢复 |
| Web 转圈「正在连接…」 | 查容器是否 up、防火墙 **1882**；旧版串口挂掉会杀 uvicorn，新版应仍可连 |
