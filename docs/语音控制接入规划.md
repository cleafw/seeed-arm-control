# 语音控制接入规划 — 分阶段实施与验收

> 工程：`seeed-arm-control`  
> 依据：`docs/通用机械臂方案规划.md` §5 / 阶段 5  
> 原则：**Voice 永不直连电机**；一律调 Core REST；弱算力可不部署 Voice。  
> 更新日期：2026-08-27

---

## 0. 当前基线（开工前共识）

| 项 | 现状 |
|----|------|
| Core 录播 / 急停 / 跟随 / 校准 | 已有 REST + WS |
| 语音代码 / 容器 | **本仓库尚无**（需新建或外挂现有 Jetson voice 服务） |
| 命名姿态 API | **尚无**（语音常用「去某姿势 / 执行某动作」依赖它） |
| `VOICE_ENABLED` / health | **尚无** |
| UI 语音入口 / 策略 | **尚无** |

**总体验收目标（全部阶段结束后）：**

1. Pi / Mock：**无语音入口**（或明确灰显「未部署」），跟随录播不受影响。  
2. Jetson / 本机开 Voice：能听懂有限意图 → 只通过 Core API 驱动机械臂。  
3. 策略可选：`follow_only` / `voice_in_follow` / `follow_first` / `voice_first`。  
4. 语音执行期间与主臂跟随不抢写电机（Core 单写者）。

---

## 1. 架构约定（各阶段共用）

```text
麦克风 / ASR / LLM / TTS          ← Voice 模块（可选进程/容器）
        │ 仅 HTTP
        ▼
   意图 Intent JSON
        │
        ▼
Core FastAPI（本仓库）            ← 唯一写电机入口
  pause / resume / play / stop
  free_move / recover
  named_pose / play action …
        │
        ▼
Leader / Follower Drivers
```

| 规则 | 说明 |
|------|------|
| 单写者 | 任意时刻只有 Core 控制线程写从臂 |
| 意图白名单 | Voice 只能发已登记意图；未知意图拒绝并 TTS 提示 |
| 能力探测 | Core 暴露 `GET /api/voice/capability`；UI / Voice 都读它 |
| 部署形态 | `core`（无语音）与 `core+voice` 两套 compose profile |

## 2. 分阶段计划

### 阶段 V0 — 合约与意图清单（约 0.5～1 天）【文档，不写驱动】

| 步骤 | 内容 | 产出 |
|------|------|------|
| V0.1 | 冻结意图白名单（中文示例 + 英文 id） | 本文 §3 表定稿 |
| V0.2 | 定义 Intent JSON schema（id / slots / request_id / source） | `docs/voice-intent.schema.json` 或 Markdown 表 |
| V0.3 | 映射：Intent → 现有/待建 Core API | 对照表 |
| V0.4 | 明确策略四态状态机简图（与跟随冲突时的行为） | 状态图 |

**验收 V0**

- [ ] 评审通过：意图 ≤ 第一期可实现范围（不做开放域闲聊控臂）  
- [ ] 每条意图都有对应 Core API 或标注「阶段 Vx 才做」  
- [ ] 无「Voice 直连串口/CAN」的设计项

---

### 阶段 V1 — Core：语音就绪 API 与能力开关（约 1～2 天）

| 步骤 | 内容 | 产出 |
|------|------|------|
| V1.1 | 配置：`VOICE_ENABLED`、`VOICE_HEALTH_URL`、`VOICE_POLICY` 默认 | `config.py` + env 示例 |
| V1.2 | `GET /api/voice/capability`：`enabled` / `reachable` / `policy` / `supported_intents` | REST |
| V1.3 | 可选：Core 定时 ping Voice health（失败 → capability.reachable=false） | 后台探测 |
| V1.4 | Snapshot / health 增加 `voice: {…}` 字段供 UI | WS + `/api/health` |
| V1.5 | `POST /api/voice/intent`（或 `/api/intents`）：校验白名单 → 调内部命令 | REST 入口 |

**验收 V1（Mock 即可）**

- [ ] `VOICE_ENABLED=0` 时 capability.enabled=false  
- [ ] `VOICE_ENABLED=1` 但 health 不通 → enabled=true, reachable=false  
- [ ] 用 curl 投递 `pause` / `play` 等意图，行为与现有按钮一致  
- [ ] 未知意图返回 4xx，不改变机械臂状态  
- [ ] 录制/回放进行中投递冲突意图：按策略拒绝或排队（至少拒绝并有明确 detail）

---

### 阶段 V2 — Core：命名姿态 / 动作别名（约 1～2 天）

语音高频：「回到初始位」「抓取姿势」「执行动作 xxx」。

| 步骤 | 内容 | 产出 |
|------|------|------|
| V2.1 | 命名姿态存储：`recordings/named_poses.json`（或复用 actions 元数据别名） | 持久化 |
| V2.2 | REST：`GET/PUT /api/named_poses`，`POST /api/named_poses/{id}/goto` | API |
| V2.3 | goto：从当前从臂位姿 transition → 目标（复用现有 blend） | Controller |
| V2.4 | 动作别名：语音名 → `action_id`（可挂在 ActionMeta.name / 别名表） | 查询接口 |
| V2.5 | 意图 `goto_pose` / `play_action` 接到 V1 入口 | 联通 |

**验收 V2**

- [ ] 手动 API：保存姿态 → goto → 从臂平滑到达（Mock 看 snapshot 关节变化）  
- [ ] 意图 `play_action` 能按名称找到动作并 loop/once  
- [ ] 无校准姿态/动作时错误信息可被 Voice TTS 复述（稳定 error code）

---

### 阶段 V3 — UI：能力感知 + 策略选择（约 1～2 天）

| 步骤 | 内容 | 产出 |
|------|------|------|
| V3.1 | 底栏或设置区：语音状态（不可用 / 可用 / 策略名） | React |
| V3.2 | 策略下拉：`follow_only` / `voice_in_follow` / `follow_first` / `voice_first` | 写入 Core 配置 |
| V3.3 | `capability.reachable=false` → 隐藏或灰显 + 文案「本机未部署语音」 | UX |
| V3.4 | 可选：最近一次意图 / 结果条（debug 友好） | 状态展示 |
| V3.5 | 文案表：拒绝原因（跟随优先占用中、急停中、未校准…） | 中文 |

**验收 V3**

- [ ] Mock 默认无 Voice：UI 无迷惑性「可说话」入口  
- [ ] 伪造 capability.reachable=true：策略可切换并刷新后保持  
- [ ] 策略切换不打断当前 follow（除非切到 voice_first 且正在执行语音动作）

---

### 阶段 V4 — Voice 模块最小闭环（约 2～4 天）

可先 **Mock Voice**（键盘/按钮发 Intent），再接真 ASR。

| 步骤 | 内容 | 产出 |
|------|------|------|
| V4.1 | `voice/` 或独立仓库：health + `POST /listen` 占位 | 服务骨架 |
| V4.2 | Mock：HTTP/CLI「注入一句中文」→ 规则/LLM → Intent → Core | 联调脚本 |
| V4.3 | 真 ASR 路径（Jetson）：麦克风 → 文本（选型另定，可后换） | 适配层 |
| V4.4 | TTS：执行成功/失败播报（可先打印） | 可选 |
| V4.5 | compose profile `voice`：依赖 Core 网络；不挂电机设备 | deploy |
| V4.6 | 环境变量示例与 README 一小节 | 文档 |

**验收 V4**

- [ ] 注入「急停」→ Core 进入 paused  
- [ ] 注入「解除锁定 / 恢复跟随」→ resume（需校准就绪）  
- [ ] 注入「播放 xxx」→ 找到动作并 playback  
- [ ] 拔掉 Voice 容器 → Core 仍可用；UI 显示语音不可用  
- [ ] **抓包确认**：Voice 进程无串口/CAN 访问，仅 HTTP 到 Core

---

### 阶段 V5 — 策略状态机落地（约 1～2 天）

| 步骤 | 内容 | 产出 |
|------|------|------|
| V5.1 | `follow_only`：拒绝一切非系统级语音（或仅允许急停——需产品拍板） | 策略 |
| V5.2 | `voice_in_follow`：允许 play/goto/pause；不暂停主臂映射 | 策略 |
| V5.3 | `follow_first`：主臂近期有运动 → 语音动作排队或拒绝 | 策略 |
| V5.4 | `voice_first`：执行语音动作前 pause 跟随；结束后回 follow 或 paused | 策略 |
| V5.5 | 单测 / Mock 脚本覆盖四种策略冲突场景 | 验收脚本 |

**验收 V5**

- [ ] 四种策略各有 ≥2 个冲突用例通过  
- [ ] voice_first 执行中掰主臂：从臂不跟（或符合文档）  
- [ ] follow_first 主臂运动中发 play：拒绝或排队，行为与文案一致

---

### 阶段 V6 — 现场部署与回归（约 1～2 天）

| 步骤 | 内容 | 产出 |
|------|------|------|
| V6.1 | Pi：`core` only 镜像/compose 清单 | 部署说明 |
| V6.2 | Jetson：`core+voice`；设备节点只给 Core | 部署说明 |

| V6.4 | 回归：无语音跟随录播；有语音急停/播放/策略 | 测试清单勾选 |

**验收 V6**

- [ ] 两套部署文档可照做  
- [ ] B601（或当前默认配套）无语音回归通过  
- [ ] 有语音路径：至少急停 + 播放一个已录动作打通

## 3. 第一期意图白名单（建议冻结）

| Intent id | 中文示例 | Core 动作 | 最早阶段 |
|-----------|----------|-----------|----------|
| `estop` | 急停 / 停下 | `POST /api/pause` | V1 |
| `resume` | 解除锁定 / 继续跟随 | `POST /api/resume` | V1 |
| `stop_play` | 停止播放 | `POST /api/actions/stop` | V1 |
| `play_action` | 播放「挥手」 | play by name/id | V2 |
| `goto_pose` | 回到初始位 | named_pose goto | V2 |
| `free_move` | 自由拖动 | `POST /api/free_move` | V1 |
| `start_record` / `stop_record` | 开始/结束录制 | record API | V1（可选，慎用） |
| `set_policy` | 切换语音策略 | 配置 API | V3 |

**第一期不做：** 开放域「把杯子放到左边」、视觉伺服、多臂编排。

## 4. 推荐推进顺序（逐步开工）

```text
V0 合约/意图冻结     ← 先评审，再写代码
  → V1 Core 能力开关 + intent 入口   ← Mock curl 验收
  → V2 命名姿态 / 动作别名
  → V3 UI 策略与灰显
  → V4 Mock Voice → 真 ASR（可拆）
  → V5 策略状态机打磨
  → V6 双部署与文档回归
```

**与总方案关系：** 本文件 = 总方案「阶段 5」的展开；不阻塞阶段 2～4 的臂型检测/SO-ARM，但 **V2 goto 依赖现有 transition/playback 稳定**。

## 6. 待你拍板（影响 V0/V1）

1. **Voice 代码落点**：本仓库 `voice/` 子目录，还是独立仓库只 HTTP 调 Core？  
2. **`follow_only` 是否仍允许语音急停？**（建议：允许，安全优先）  
3. **第一期是否要「开始/停止录制」语音？**（误触发风险高，可放到 V6 后）  
4. **ASR/LLM 选型**：先规则关键词（稳），还是一上来 LLM（灵、但要 Jetson）？

确认以上四点后，从 **V0 → V1** 开始实现。
